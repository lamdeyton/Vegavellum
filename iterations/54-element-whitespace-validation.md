# R54: tags/sources 元素级前后空格校验（R39/R53 同型补全）

**轮次**: R54
**日期**: 2026-07-24
**主题**: Horizontal 审计发现 tags/sources 元素级缺少前后空格校验，与 R39 空白字符串校验和 R53 字段级前后空格校验不一致
**状态**: 已完成
**相关模式**: R39, R53, R31, R35

## 背景

R39 为 tags/sources 元素添加了纯空白字符串校验（`t.trim() === ''`），但遗漏了前后空格校验（`t !== t.trim()`）。

R53 为所有 free-text 字段（Project 4 个 + Category 5 个）添加了前后空格校验，确立了"同型字段使用相同校验"的模式。

## Gap 发现

### Horizontal 审计：元素级 vs 字段级

| 层级 | 类型 | 空字符串 | 纯空白 (trim==='') | 前后空格 (value!==trim) | 内容/格式校验 |
|------|------|---------|-------------------|----------------------|--------------|
| 字段级 free-text | string | ✓/隐式 | ✓ (R37) | ✓ (R53) | ✓ (SPDX/URL-friendly 等) |
| 元素级 tags/sources | string[] | ✓ (R35) | ✓ (R39) | **✗** | ✓ (枚举/唯一性) |

**Gap**: tags/sources 元素级缺少前后空格校验，与字段级（R53）和元素级空白字符串（R39）不一致。

## 攻击向量验证

构造攻击样本：

```yaml
tags: [" astro ", "ssr "]
sources: [" curator-curated "]
```

验证结果（修复前）：

| 字段 | 行为 | 问题 |
|------|------|------|
| tags 元素 " astro " | 静默通过 | 渲染 `# astro `（含空格），不美观 |
| tags 元素 "ssr " | 静默通过 | 渲染 `# ssr `（含空格），不美观 |
| sources 元素 " curator-curated " | 报"不在枚举内" | **误导性错误**，真实问题是前后空格（R31 模式违反） |

## 影响分析

| 维度 | 影响 | 严重度 |
|------|------|--------|
| 数据质量 | tags/sources 含前后空格，数据不干净 | MINOR |
| 用户体验 | 标签渲染含空格，视觉不整齐 | MINOR |
| 贡献者体验 | sources 前后空格时报"不在枚举内"，误导贡献者（R31 违反） | MINOR |
| 同型一致性 | 字段级有前后空格校验，元素级没有，模式不一致 | MINOR |

## 修复方案

### validator 侧

在 tags 和 sources 元素级校验中，在**空白字符串校验之后、唯一性校验之前**添加前后空格校验。

校验顺序（与 R39 模式一致）：
1. 类型校验
2. 非空校验
3. 纯空白校验 (trim() === '') — R39
4. **前后空格校验 (value !== value.trim())** — R54 ← 新增
5. 唯一性校验
6. 内容校验（枚举/格式等）

前后空格校验后 `continue`，跳过唯一性和内容校验，避免误导性错误（R31 模式：空性/格式错误优先于内容校验）。

### 同型对齐矩阵

| 层级 | 空字符串 | 纯空白 | 前后空格 | 唯一性 | 内容校验 |
|------|---------|--------|---------|--------|---------|
| 字段级 free-text | ✓/隐式 | ✓ (R37) | ✓ (R53) | - (单值) | ✓ |
| 元素级 tags/sources | ✓ (R35) | ✓ (R39) | ✓ (R54) | ✓ (R35) | ✓ |

## 验证

## 模式确立

### 同型对齐全链路模式（再次确认）

字段级 ↔ 元素级的校验深度必须对齐：
- 空字符串校验：字段级 ✓ → 元素级 ✓ (R35)
- 纯空白校验：字段级 ✓ (R37) → 元素级 ✓ (R39)
- 前后空格校验：字段级 ✓ (R53) → 元素级 ✓ (R54)

### R31 模式扩展（元素级）

元素级校验也遵循"空性/格式错误优先于内容校验"原则：
- 类型错误 → 跳过后续所有校验（continue）
- 空字符串 → 跳过后续校验
- 纯空白 → 跳过后续校验
- 前后空格 → 跳过后续校验（R54 新增）
- 内容校验（枚举/格式） → 最后执行

### 攻击样本验证模式（再次确认）

每发现一个 gap，先构造攻击样本验证 gap 存在，修复后用同一攻击样本验证修复生效，确保防御性检查完整有效。
