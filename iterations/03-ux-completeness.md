# R3：用户体验完善

> 触发：R1/R2 审计发现子目标 3（可访问性）和子目标 6（可扩展性）部分缺失。5 个空分类点进去是干瘪空状态，无 404 页面，无贡献指南，无 LICENSE。

## 审计发现

### G2：空分类体验差

**症状**：5 个空分类（backend-framework/database/devops/security/libraries）点进去只显示一句"该分类暂无已收录项目。"

**后果**：用户不知道接下来该做什么，感觉项目"荒芜"。

**修复**：改为"该分类暂无已收录项目"+ "如果你知道优秀的开源项目，欢迎通过 PR 提名收录。"+ "← 浏览其他分类"链接。

### G3：无自定义 404 页面

**症状**：Astro 默认有 404，但未定制，用户访问错误路径看到的是裸页面。

**修复**：创建 `src/pages/404.astro`，含大号 404、说明文字、"← 返回首页"CTA。

### G4：首页缺少统计

**症状**：首页只有 slogan 和分类列表，无项目总数/分类数信息。

**后果**：用户无法快速判断这个索引的覆盖程度，缺乏信任感。

**修复**：首页 hero 下方添加 3 个统计数字：已收录项目数、已覆盖分类数、总分类数。

### G5：无 CONTRIBUTING.md

**症状**：贡献者不知道如何提名项目、数据格式是什么、如何本地验证。

**修复**：创建 `CONTRIBUTING.md`，包含：
- 项目数据文件格式（必填/可选字段、status 状态说明）
- 分类 id 对照表
- 本地验证步骤（npm run validate / dev / build）
- PR 提交流程
- 收录标准

### G6：无 LICENSE 文件

**症状**：开源项目无 LICENSE 文件，法律上不构成开源授权。

**修复**：创建 MIT LICENSE 文件。

## 实施的变更

### 新增文件
1. `src/pages/404.astro` — 自定义 404 页面（大号 404 + CTA）
2. `CONTRIBUTING.md` — 贡献指南（数据格式/分类/验证/PR 流程/收录标准）
3. `LICENSE` — MIT 许可证

### 修改文件
4. `src/pages/index.astro` — 首页添加统计区块（3 个数字）
5. `src/pages/category/[id].astro` — 空分类 CTA（标题 + 提示 + 链接）+ 样式
